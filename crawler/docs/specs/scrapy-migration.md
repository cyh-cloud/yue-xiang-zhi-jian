# Scrapy 全面迁移：8 个采集项目与小样本验证

状态: ready-for-agent

## Problem Statement

当前采集层由手写发现器、请求代码、来源解析器和统一运行入口组成。实时请求、原始证据写入、采集侧准入和候选标准实体写入集中在同一条运行路径里，站点差异主要通过条件分支处理。随着来源增加，选择器、限速、文件下载、robots 判断和失败处理容易在来源之间复制，任何公共契约变化也可能迫使多个来源一起修改。

现有来源的形状差异明显。中国非物质文化遗产网使用分页 JSON 和详情页，招聘来源使用服务端 HTML 或已保存详情，方言和研究来源具有不同栏目结构，农产品与地理标志来源依赖 XLSX、PDF 和公告附件。它们共享来源登记、权利、证据、去重、采集准入和候选标准实体契约，但不共享站点选择器和运行参数。

项目需要把实时采集迁移到 Scrapy。迁移必须同时做到站点项目隔离、公共契约统一和使用单个实时写入路径，并且不能把 Scrapy Pipeline 变成业务库写入器。本轮还要为 8 个正式来源建立可执行项目和验证证据，其中 6 个完成小样本联网验证，2 个文件来源完成骨架、接口和 fixture 验证。

本规格描述迁移目标、共享接口、项目范围、验证门和边界。它不直接实现代码，也不修改业务库结构、后端或前端。

## Solution

建立一套以 Scrapy 为默认且最终实时采集执行层的新采集架构。

每个业务内容采集网站对应一个独立 Scrapy 项目，项目身份使用稳定的来源 ID。共享包提供所有项目共用的 Item 契约、原始证据、采集库写入、来源注册表读取、采集侧准入、去重、运行日志、robots 事实和测试辅助。站点项目只保留自己的 Spider、设置、选择器、分页、站点 helper、站点依赖声明和运行说明。

所有项目共用一个 uv 依赖根，只维护一份根依赖清单和一份锁文件。每个项目仍是独立包和独立运行单元，不复制锁文件，也不建立第二套相互漂移的依赖环境。

采集数据生命周期固定为：

raw -> stage -> 采集库 std 候选标准实体 -> 转换器 -> 业务实体（draft 或 pending_review）-> 审核 -> 同一条业务实体变为 published -> 前端只查询 published。

raw、stage 和采集库 std 候选标准实体位于采集库，没有业务主键，前台不可见。业务实体位于业务库，有稳定业务主键和生命周期状态。发布实体不是独立表或第二条记录，它就是同一条业务实体审核通过后的 published 状态。审核记录结论、审核人和时间并更新状态，不复制业务内容。

Scrapy 项目、Item 和 Pipeline 的写入边界止于采集库。Pipeline 可以保留 raw 证据、写 stage、写候选标准实体，也可以把候选标记为 candidate、deferred 或 blocked，但不得打开业务库、导入业务写入模块、调用转换器或改变业务审核与发布状态。

候选状态固定为：

- `candidate`：数据完整，可以进入转换器。
- `deferred`：数据完整但当前暂不转换或发布。`robots.txt` 返回 404 时使用这个状态，原因写 `robots:not-found`。
- `blocked`：数据不完整、解析失败、权利不明、访问被明确禁止或存在其他真实阻断。

`robots.txt` 返回 404 不阻断采集和采集库写入。它只表示没有可读规则，不表示获得授权，也不自动获得业务发布资格。403、5xx、`unknown`、明确 Disallow、登录要求、验证码和付费墙仍按真实阻断处理。

转换器继续是 Scrapy 运行之外的独立跨库阶段。它从采集库读取候选标准实体，执行自然键、来源优先、冲突、人工字段保护、批次和回滚，并把结果交给业务库。本轮迁移不把转换器塞进 Scrapy 项目，也不在采集失败时直接改变业务库。

本轮正式范围恰好是 8 个项目：

| 来源 ID | 本轮目标 | 验证方式 |
| --- | --- | --- |
| `ihchina` | JSON 分页、项目详情和必需关联字段 | 5 条列表加 5 条详情联网小样本 |
| `nzrc` | 招聘列表、详情和保存式样本 | 5 条列表加 5 条详情联网小样本 |
| `nongmuhr` | 招聘列表、详情和分页边界 | 5 条列表加 5 条详情联网小样本 |
| `dialect-org` | 方言点、词条和来源关系 | 5 条列表加 5 条详情联网小样本 |
| `cass-linguistics` | 公开研究资料与栏目分页 | 5 条列表加 5 条详情联网小样本 |
| `feiyiw` | 非遗资讯列表与文章详情 | 5 条列表加 5 条详情联网小样本 |
| `aqsc-moa` | XLSX 和公告附件的项目骨架 | 只做 fixture、接口和契约测试 |

## Implementation Decisions

### 执行层与项目隔离

- Scrapy 是默认且最终的实时采集执行层。现有手写实时实现按来源逐步迁移，迁移完成的来源以对应 Scrapy 项目作为唯一实时入口。
- 一个采集网站对应一个独立 Scrapy 项目，项目身份使用来源注册表中的稳定来源 ID。
- 一个项目拥有自己的 Spider、settings、middlewares、pipelines 组合、站点 helper、站点依赖声明和运行说明。
- 站点之间不共享 Spider，也不使用一个参数化 Spider 承载多个网站。
- 共享包不包含站点选择器、站点分页、站点限速值、站点授权判断或业务字段映射。
- 项目目录、包名和项目入口在第一个实现票据中冻结，冻结后其他票据不得各自改名。

### 单一 uv 依赖根

- 所有项目共用一个 uv 依赖根，只维护一份根依赖清单和一份锁文件。
- 每个项目保留独立代码、设置和测试入口，不复制锁文件。
- 站点专用依赖在共享项目元数据中按项目声明，并由对应项目入口选用。
- 共享包不依赖任何站点专用包。
- 依赖升级必须在共享锁文件中完成，并至少通过一个已迁移项目的 fixture 回放。

### 共享 Item 契约

共享 Item 表达已经解析但尚未完成所有采集侧验证的结果。Item 至少包含以下逻辑字段组：

| 字段组 | 内容 | 约束 |
| --- | --- | --- |
| 来源身份 | `source_id`、`source_item_id` | `source_id` 必须来自来源注册表；`source_item_id` 使用来源内稳定键 |
| 发现与详情 | `source_url`、`long_term_url`、`detail_url`、`detail_url_status`、`fetch_url`、`locator` | 有直接详情页时 `detail_url_status=direct`；没有时 `missing`，必须有长期承载页 URL 和非空 locator |
| 权利 | `rights_status`、`attribution_required`、`attribution_text`、`rights_evidence_url` | 默认来自来源注册表，记录级显式值优先，包括显式 `False`；不能用 `or` 合并 |
| 内容 | 标题、正文或结构化载荷、站点原始字段 | 站点字段保留原名，标准字段由共享归一阶段生成 |
| 证据与版本 | 请求上下文、内容类型、响应头、内容哈希、parser version、取得时间 | 内容哈希对规范化内容计算，不作为业务主键 |
| 运行 | 运行标识、模式、来源内序号 | 用于日志、计数和 raw、stage、候选对账 |
| 候选 | 候选状态、原因 | 只表达采集侧 candidate、blocked、deferred，不表达业务发布 |

站点专属字段必须可序列化，不得把 response、selector、数据库连接或未脱敏凭据放入 Item。

### 原始证据接口

- 每个实际请求或文件必须追加写入 raw 证据，保存请求 URL、最终 URL、来源 URL、长期 URL、详情 URL、详情 URL 状态、fetch URL、locator、方法、脱敏后的请求和响应头、状态码、内容类型、字节数、SHA-256、保存路径、取得时间、访问等级、权利字段、robots 结论、运行标识和错误信息。
- 原始响应按请求追加，同一 URL 多次取得允许多条 raw 记录，不更新旧证据。
- 文件另存文件级证据，包含文件 URL、承载页、长期 URL、详情 URL 状态、locator、本地路径、文件名、MIME、大小、SHA-256 和取得时间。
- 敏感请求头必须脱敏。真实 Cookie、Authorization、签名凭据和登录态不得写入证据。
- 单文件超过 100MB 时不保存文件本体，只写超限说明。临时签名 URL 只进入 fetch 字段，不进入长期 URL 或详情 URL。
- 原始证据接口返回稳定的 raw 证据标识，stage 和候选写入必须引用该标识或运行关联。

### stage 写入接口

- stage 按单个来源自身结构保存解析结果，保留来源字段、来源内编号、标题摘要、locator、版权和取得时间。
- 当前中性 stage 表没有来源专属查询列时，来源差异进入 `extra`。只有某来源确实需要可查询的专属列时，才由单独票据明确冻结 schema 扩展。
- stage 幂等键至少使用 raw 证据标识和来源内条目标识。重复运行允许追加新的 raw 证据，但同一证据内的同一来源条目不重复。
- 没有直接详情 URL 的记录仍可进入 raw 和 stage。承载页 URL 和 locator 完整时，可以继续进入候选、业务实体和发布审核。
- stage 写入不得调用转换器，不得打开业务库。

### 采集库 std 候选写入接口

- 候选写入只接收已经归一成跨来源标准字段的实体，按现有标准实体自然键或来源关系键幂等写入。
- 候选状态至少包括 candidate、blocked 和 deferred。业务发布状态不得复用这些含义。
- 当前物理 schema 若没有独立候选状态列，必须在首个契约票据中明确选择向后兼容扩展，不能把业务发布状态当作候选状态使用。
- 候选写入必须先完成来源注册表判断、权利检查、访问等级检查、robots 结论、必需字段检查和详情 URL 门禁。
- 缺少直接详情 URL 的附件行和动态查询行使用承载页 URL 加 locator 进入候选标准实体。临时签名地址只进入 `fetch_url` 或 raw 证据。承载页或 locator 缺失时写 `deferred`。
- 候选写入不产生业务主键，不提供前台可见性，不授予 published 状态。
- 同一来源重复运行不得产生重复候选。内容更新可以更新规范化字段和最后发现时间，但必须保留 raw 证据和来源关系。

### 采集侧准入

共享准入至少检查来源是否启用、状态是否允许执行、访问等级、权利状态、robots 结论、必需字段、URL 形态、详情 URL 状态和 locator。检查结果只能是以下之一：

1. 数据完整且可进入转换器，候选状态为 candidate。
2. 数据完整但当前暂不转换或发布，候选状态为 deferred，并记录原因，例如 `robots:not-found`。
3. 数据不完整、解析失败、权利不明或访问被明确禁止，候选状态为 blocked，并记录原因。
4. 拒绝本次请求或项目运行，记录来源级或运行级原因。

采集侧准入不决定业务发布。权利不明、访问受限或详情缺失属于采集和转换的输入条件，不得被解释成业务审核结论。

### Pipeline 与转换器边界

- Scrapy Item Pipeline 只组合共享证据、stage、候选写入、去重、准入、日志和站点内失败记录。
- Pipeline 不打开业务库，不导入业务写入模块，不调用转换器，不写业务审核表，不修改发布状态。
- 转换器是独立跨库阶段，读取候选标准实体，执行自然键、来源优先、冲突、人工字段保护、批次和回滚。
- 目标流程中的业务实体和发布实体状态变化属于转换器和业务审核边界。本轮迁移不得为了测试这条链路而修改业务库 schema、后端或前端。
- 现有转换器仍以 dry-run 为主时，本轮必须验证它可以稳定读取候选、跳过非候选并按批次记录结果。启用真实业务写入是独立变更，不能由站点项目顺带完成。

### 八个项目与验收范围

- `ihchina`：验证 JSON 分页、详情页、项目主记录和现有契约要求的关联字段。联网小样本目标为 5 条列表和 5 条详情。
- `nzrc`：验证招聘列表、详情、保存式 fixture 和公开字段边界。联网小样本目标为 5 条列表和 5 条详情。
- `nongmuhr`：验证招聘列表、分页、详情和过期时间表达。联网小样本目标为 5 条列表和 5 条详情。
- `dialect-org`：验证首页列表、词条详情、方言点与词条来源关系。联网小样本目标为 5 条列表和 5 条详情。
- `cass-linguistics`：验证公开栏目分页、研究文章和公开正文边界。联网小样本目标为 5 条列表和 5 条详情。
- `feiyiw`：验证文章列表、文章详情和补充资讯边界。联网小样本目标为 5 条列表和 5 条详情。
- `aqsc-moa`：本轮建立项目骨架、共享接口组合、XLSX 和公告附件 fixture 回放，不执行真实文件采集。下一阶段必须补 live 小样本，覆盖附件下载、XLSX 解析、文件哈希、工作表行号 locator、公告承载页 URL、`detail_url_status=missing` 和 `deferred` 候选。
- `cnipa`：本轮建立项目骨架、共享接口组合、PDF 或公告附件 fixture 回放，不执行真实文件采集。下一阶段必须补 live 小样本，覆盖 PDF 下载、表格解析、文件哈希、页码和序号 locator、公告承载页 URL、`detail_url_status=missing` 和 `deferred` 候选。

`aqsc-moa` 和 `cnipa` 的骨架必须能证明项目可以被发现、配置可以加载、fixture 可以回放到 raw、stage 和符合门禁的候选边界、文件证据和 locator 规则有效。不得把骨架测试写成真实联网或全量文件验证。

### 旧实现与切换

- 迁移期旧手写实现只在对应来源尚未接管时保留实时写入权。
- 同一来源在迁移期同一时刻只能有一个实时写入者。
- Scrapy 项目先在隔离库完成 fixture 对照和实时 canary，再以来源为粒度切换正式写入权。
- canary 使用独立采集库、下载目录和运行标识，不写正式采集库，不写业务库。
- 正式来源全部切换后，删除或封存旧实时入口，只保留 Scrapy 一条实时写入路径。不设计长期双入口 writer 路由。
- 首次切换前保留旧实现作为回退点。回退使用上一个运行版本和数据库快照，不删除已保存的 raw、stage 或候选证据。

### Fixture 所有权

- 公共 fixture 根继续按来源 ID 归属。每个项目只读取自己的来源目录，不在项目目录内复制 fixture。
- 现有目录名与来源 ID 不一致时，在第一个契约票据中规范化到来源 ID。本轮已将 `aqsc` 规范化为 `aqsc-moa`，不保留隐式别名映射。
- fixture 必须是最小、脱敏、体积受控的真实结构样本或确定性合成样本。
- 项目必须能离线回放 fixture，并比较来源内自然键、必需字段、URL、locator、版权字段、候选结果和跳过原因。
- 真实下载证据继续放在被忽略的下载根，不进入公开 fixture。

### 来源注册表与排除来源

- 来源注册表是来源启用状态、状态、访问等级、权利、运行模式和归属文档的唯一真相源。
- `5ajob` 不建 Scrapy 项目，不启用 live，不重新开启采集，只保留现有离线解析器和 fixture 测试。来源注册表保持禁用。
- `zhongguoyuyan` 保持 excluded。
- `cnopendata` 保持 deferred。
- `open-meteo` 和 `qweather` 不建立 Spider。
- 不新增正式来源。实际采集发现数据不足后，再按来源扩展流程单独提出扩大范围。

### 天气边界

- `weather` 是后端运行时 API 客户端，不属于 Scrapy 项目，不进入采集库、转换器或发布门禁。
- 天气请求、DTO 解析和 15 分钟运行时缓存继续由运行时客户端负责。
- `open-meteo` 和 `qweather` 保持 draft 与禁用状态，只保留候选元数据。
- 本轮不把天气客户端从现有位置搬走，也不为了迁移天气修改后端。

### 框架例外

- 只有出现可复现的 Scrapy 能力边界时，才允许为单个来源引入其他框架。
- 能力边界必须提供目标站点、请求、缺失能力、最小原型或失败证据，并说明为什么 Scrapy 文档化的 Spider、middleware、scheduler、addon、pipeline 或受支持扩展无法满足。
- 替代方案不得绕过登录、验证码、付费墙、robots 或其他访问控制。
- 替代框架只作用于该来源项目，继续使用共享 Item、原始证据和采集库写入。
- 必须新增 ADR 或获得项目负责人明确批准。不熟悉 Scrapy、需要浏览器脚本、需要解析 XLSX 或 PDF、需要自定义重试或限速不构成例外。

### 运行、日志和错误

- 每次项目运行必须产生运行标识、开始时间、结束时间、模式、来源、发现数、请求数、raw 写入数、stage 写入数、候选状态计数、跳过数、失败数和错误摘要。
- 404、403、429、5xx、超时、robots 结论、登录边界、解析失败和空结果必须显式记录。
- 部分成功只能报告 partial 或等价状态，不能报告 succeeded。
- 日志不得包含 Cookie、Authorization、签名凭据、个人简历、未脱敏联系方式或文件正文。
- 站点阻断时记录重试条件和证据位置，不自动引入代理池、验证码处理或访问控制绕过。

### Schema 与兼容

- 本轮不修改业务库 schema、后端或前端。
- 采集库 schema 如因候选状态、运行关联或项目隔离需要扩展，必须由票据明确列出字段、迁移顺序、默认值、兼容策略和回滚方式。
- 现有 raw、stage 和 std 物理表名保持兼容。文档中的 std 只能指采集库候选标准实体，不能指业务实体或发布实体。
- 新列必须允许旧数据继续读取，旧实现和现有测试在迁移期仍可运行。

## Testing Decisions

### 最高测试缝

最高测试缝是来源注册表与共享采集契约的交界。所有项目从同一个来源注册表读取启用状态、访问等级、权利和运行模式，所有项目通过同一组证据、stage、候选和准入接口写入采集库。测试应优先验证这一层，避免为每个站点复制公共断言。

第二个测试缝是项目 fixture 回放。每个项目把同一份最小 fixture 从 Spider 或解析入口推进到 raw、stage 和候选边界，验证项目组合正确，而不是只测试孤立选择器。

第三个测试缝是联网 canary。联网测试只验证小样本真实可用性和访问边界，不把全量采集作为本轮通过条件。

第四个测试缝是转换器输入契约。测试验证转换器可以读取候选、跳过非候选、记录批次结果，并证明 Scrapy 运行路径不会打开业务库。

### 好测试的标准

- 测试外部可观察行为：Item 逻辑字段、raw 证据行、stage 行、候选自然键、候选状态、运行计数、日志摘要和错误结论。
- 不锁 Spider 内部方法名、SQL 字符串、具体选择器实现或日志排版。
- fixture 测试默认不访问网络。联网测试显式启用，只作用于获准来源和小样本。
- 同一 fixture 连续回放两次，验证 raw 追加、stage 幂等、候选不重复和计数可对账。
- 缺少直接详情 URL 但有承载页和 locator、承载页或 locator 缺失、权利不允许、来源禁用、robots 404 写 deferred、robots 明确拒绝和解析失败必须有反例测试。
- 空列表、全部请求失败和全部条目被跳过必须产生显式失败或 partial，不能产生 succeeded。
- 文件证据测试覆盖大小、SHA-256、MIME、locator、临时 URL 和 100MB 超限。
- 跨库边界测试覆盖导入图和运行路径，证明 Scrapy 项目不导入业务写入模块，不打开业务库，不调用转换器。

### 共享包测试

共享包至少覆盖：

1. Item 必填字段、URL 和 locator 不变量。
2. raw 请求和文件追加、哈希、脱敏、超限和临时 URL 处理。
3. stage 幂等和来源字段保留。
4. 候选自然键、candidate、deferred、blocked、deferred 与 blocked 分开计数和重复运行。
5. 来源注册表禁用、权利、访问等级、运行模式和缺失来源。
6. robots 事实和访问结论记录。
7. 运行计数、partial 和 failed 的错误模型。
8. 项目导入图不进入业务库。

现有 schema 契约测试、raw 证据测试、发布门禁测试、来源注册表测试和转换器 dry-run 测试是共享包测试的先例。新测试应复用这些行为断言，不复制其实现。

### 项目测试矩阵

| 项目 | 离线回放 | 联网小样本 | 关键断言 |
| --- | --- | --- | --- |
| `ihchina` | 必须 | 5 列表加 5 详情 | 项目身份、详情 URL、项目字段、raw 和候选 |
| `nzrc` | 必须 | 5 列表加 5 详情 | 岗位自然键、详情字段、公开字段边界 |

| `dialect-org` | 必须 | 5 列表加 5 详情 | 方言点、词条、来源关系和音频状态 |
| `cass-linguistics` | 必须 | 5 列表加 5 详情 | 栏目分页、研究文章和公开正文 |
| `feiyiw` | 必须 | 5 列表加 5 详情 | 文章自然键、列表日期和详情正文 |

联网样本应保存来源 URL、取得时间、请求结果、字段摘要、候选计数和失败摘要。若站点真实阻断，测试记录阻断证据和重试条件，验收结论为 blocked 或 partial；robots 404 不是阻断，必须记录 `not-found` 并统计 deferred。不得通过修改 fixture 冒充联网成功。

### 验收门

1. 共享契约测试通过，旧实现现有测试仍通过。
2. 每个项目可被发现、可加载设置，并有独立 fixture 回放入口。
3. 8 个项目的 fixture 回放均通过。
4. 前 6 个项目分别完成 5 条列表和 5 条详情的小样本联网尝试。成功时保存证据；阻断时保存阻断证据。
5. `aqsc-moa` 和 `cnipa` 本轮没有真实文件采集记录，验收依据骨架、fixture 和接口契约；下一阶段 live 小样本是独立验收门。
6. 连续两次回放同一 fixture，raw 按请求追加，stage 和候选不重复，计数可对账。
7. 缺详情、承载页或 locator 缺失、权利不允许、来源禁用、robots 404、robots 明确拒绝和解析失败的反例全部通过。
8. Scrapy 运行路径不打开业务库，不调用转换器。
9. 来源注册表、项目清单、ADR、迁移计划和本规格中的 8 个项目一致。
10. 文档、路径、JSON、Python 静态检查和 diff 检查通过。

## Out of Scope

- 不把 `5ajob`、`zhongguoyuyan`、`cnopendata`、`open-meteo` 或 `qweather` 建成 Scrapy 项目。
- 不把天气放进 Scrapy、采集库或转换器。
- 不新增正式来源，不把来源扩展候选提前提升为项目。
- 不执行全量采集，不承诺 3610 个非遗详情、全部招聘历史页或全部附件在本轮完成。
- 本轮不对 `aqsc-moa` 和 `cnipa` 执行真实文件采集。两者的 live 小样本、附件解析质量和全量文件对账属于下一阶段。
- 不修改业务库 schema、后端、前端或业务审核界面。
- 不在本轮启用尚未具备的转换器业务库写入能力。
- 不建立发布镜像表，不复制业务实体生成发布实体。
- 本轮不删除旧手写实时实现。正式来源全部切换后，旧实时入口必须删除或封存，只保留 Scrapy 一条实时写入路径。
- 不建立生产调度平台、代理池、验证码处理、反爬绕过或登录自动化。
- 不采集个人简历、求职者隐私、登录后联系方式、付费内容或 robots 明确禁止的页面。robots 404 不按禁止处理，允许 raw、stage 和 deferred 候选写入。
- 不修改 ADR 0001。ADR 0002 和 ADR 0003 的采集口径以最新项目负责人裁决为准，本规格执行其边界。
- 不创建 PR，不创建子 issue，不关闭任何 issue。

## Further Notes

### 已发现的上下文冲突

1. 现有转换器仍以 dry-run 为主，而 ADR 的目标流程包含业务实体写入、审核和 published 状态。两者不矛盾，但本轮不能把 dry-run 通过写成业务发布链路已实现。真实业务写入必须作为独立变更处理。
2. 现有 fixture 目录并非全部与来源 ID 完全一致，例如农产品来源 ID 与旧目录名存在差异。本轮已规范化为 `evidence/<source_id>/`，不引入隐式别名映射。
3. 当前物理 std 表使用历史命名的发布状态字段，没有独立候选状态列。候选状态需要显式表达时，必须通过向后兼容的 schema 扩展完成，不能把业务 published 含义塞进采集候选。
4. 旧采集规格和本地任务图记录的是上一阶段“只交付文档、不创建远程 issue”的范围。本规格只覆盖后续 Scrapy 迁移阶段，并由当前任务明确要求发布 GitHub issue。旧记录不修改，但不得再用旧阶段范围阻止本轮实现。
5. 天气运行时解析器目前位于采集代码目录中，而目标边界要求天气由后端运行时客户端负责。本轮不搬动它，也不修改后端。迁移天气归属需要单独变更，不能混入 8 个项目。
6. 来源注册表包含 14 个来源，而 Scrapy 项目只有 8 个。这是有意的范围差异，不是清单冲突。其余来源分别属于运行时、延后、排除或仅保留元数据。

### 决策指针

- 采集执行边界、术语和发布状态以 ADR 0003 为权威来源。
- 跨库分离和业务库边界以 ADR 0001 为准。
- 来源权利、访问等级和署名以 ADR 0002 与来源注册表为准。
- 原始证据、stage、URL、locator 和版权字段以现有来源契约和采集库 schema 文档为准。
- 转换器外部 interface 以现有批次转换契约文档为准。

### 实施顺序建议

1. 冻结共享 Item、证据、stage、候选、准入、日志、robots 和运行计数契约。
2. 建立单一 uv 依赖根和项目发现方式。
3. 用其中一个项目验证共享包，不新增第九个 demo 项目。
4. 并行实现各站点项目，每个项目只改自己的目录和 fixture 回放入口。
5. 先完成 8 个项目的离线回放，再执行前 6 个项目的联网小样本。
6. 完成反例、幂等、跨库边界和来源一致性验收。
7. 每个来源通过 canary 和审核后再单独切换实时写入权。全部正式来源切换完成后，删除或封存旧实时入口。

### 完成定义

本规格完成时，团队应能独立运行 8 个项目中的任意一个，离线回放其 fixture，看到 raw、stage 和候选的完整结果，并能解释每个条目为什么是 candidate、deferred、blocked 或 skipped。前 6 个项目应有真实小样本结论，后 2 个项目应有明确的骨架与 fixture 结论，并列出下一阶段 live 小样本范围。任何未完成的联网验证都必须有可复核的阻断证据和后续解除条件。

# 粤乡智匠数据采集系统设计与文档交付规格

状态: ready-for-agent

日期: 2026-10-19

## Problem Statement

粤乡智匠现有的农业、病虫害、手工技艺、方言、招聘、本土资源内容多为少量演示数据，无法支撑完整演示，也不足以验证真实业务在数据量增长后的表现。项目初期表结构仍在演进，如果直接把采集结果写入粤乡智匠业务库，来源字段、采集状态、冲突记录和原始页面会污染业务模型，后续新增或删除数据源时难以回溯，也难以撤销错误导入。

用户已收集一批农业、招聘、方言、非遗和天气网站，但缺少统一的来源目录、可复现的页面或接口定位方式、字段映射、数据质量规则、下载规则和数据库演进方案。当前阶段需要先把采集设计写清楚，为后续实现爬虫、双数据库和转换器提供依据，本次不修改粤乡智匠后端、数据库或前端。

## Solution

建立一套独立的数据采集设计，采用两套 SQLite 数据库和一层转换器:

- 采集库保存原始响应、整理后的来源数据和跨来源标准化实体，作为事实源和回溯依据。
- 粤乡智匠业务库只保存需要展示、审核和运营的数据。
- 转换器负责自然键归一、去重、字段映射、冲突记录、人工字段保护、发布控制、导入批次和回滚。

本次交付一组 Markdown 设计文档和一份机器可读来源清单，覆盖每个来源的真实入口、列表页、详情页、API、文件附件、分页参数、DOM 选择器、字段映射、样本记录、访问限制、版权状态和验证时间。文档统一放在 `crawler/docs`，下载文件统一放在 `crawler/download/<网站域名>`。

数据范围以国家级和全国性公开来源为主。农产品覆盖全国名特优新、特质农品和农业食品相关地理标志产品，包含水产。国家级非遗按 3610 个子项全量采集。招聘覆盖全国农业和乡村相关岗位。方言和历史天气只登记可接入来源，受限站点如实标注。所有可入库记录必须保留可回溯的来源页面：有单条详情页时保存直接详情 URL，没有时保存长期承载页 URL 和能定位记录的 locator。

## User Stories

1. 作为后续爬虫开发者，我想看到每个来源的真实列表页和详情页 URL，以便不用重新摸索入口就能开始实现。
2. 作为后续爬虫开发者，我想看到每个来源的请求参数和翻页方式，以便稳定获取全量数据。
3. 作为后续爬虫开发者，我想看到 JSON API 的字段说明和 HTML 页面的 DOM 选择器，以便在接口变化时有备用定位方案。
4. 作为后续爬虫开发者，我想看到至少 1 至 3 条真实样本，以便确认选择器和字段映射不是猜测。
5. 作为后续爬虫开发者，我想看到样本到采集库和粤乡智匠业务表的逐字段映射，以便直接实现转换器。
6. 作为后续审核者，我想看到每个来源的验证时间和访问结果，以便判断文档是否仍可信。
7. 作为后续审核者，我想看到每个来源独立审核记录，以便发现入口失配、选择器过期或样本缺失。
8. 作为后续审核者，我想看到来源的 robots、登录要求和授权状态，以便避免不合规采集。
9. 作为产品负责人，我想让国家级非遗项目全量进入采集库，以便后续随时扩充教学内容和筛选维度。
10. 作为产品负责人，我想让粤乡智匠前台只展示可教学的非遗项目，以便避免大量空步骤、空视频的详情页破坏体验。
11. 作为产品负责人，我想让非遗项目保留项目编号、批次、类别、申报地区和保护单位，以便支持按地区、门类和批次浏览。
12. 作为产品负责人，我想让非遗项目保留来源详情页 URL，以便用户可以跳转查看原始资料。
13. 作为产品负责人，我想让全国名特优新、特质农品和地理标志产品统一进入采集库，以便演示足够大的农产品数据量。
14. 作为产品负责人，我想让水产单独可筛选，以便农技实训覆盖鱼类、虾蟹、贝类和其他水产品。
15. 作为产品负责人，我想让农产品按认证类型、省份、县域、品类和来源筛选，以便用户快速定位产品。
16. 作为产品运营，我想让全国招聘岗位进入独立采集表，以便不污染现有企业岗位和策展招募公告。
17. 作为产品运营，我想让招聘数据只收农业和乡村相关岗位，以便平台主题保持一致。
18. 作为产品运营，我想让招聘数据保留来源站、原始详情 URL、发布时间和截止时间，以便用户回到原站报名并判断时效。
19. 作为产品运营，我想让方言数据采用方言点、词条和来源的分层模型，以便承载全国数据而不是只支持少量演示短语。
20. 作为产品运营，我想让现有方言展示表继续服务前台，以便爬虫模型升级时不影响已有页面。

30. 作为数据工程师，我想让转换器保留冲突记录和双方来源 URL，以便无法自动裁决时可以人工复核。
31. 作为数据工程师，我想让转换器保护运营手工修改过的字段，以便重跑采集不会覆盖人工结论。
32. 作为数据工程师，我想让每次导入有批次记录，以便按批次审查和撤销。
33. 作为数据工程师，我想让下载文件按网站域名归档并记录大小和哈希，以便复现采集结果且避免仓库失控。
34. 作为数据工程师，我想让超过单文件大小上限的文件只写说明文档，以便不突破 100MB 限制。
35. 作为数据工程师，我想让来源清单是机器可读的，以便后续爬虫调度器和文档检查器直接消费。
36. 作为数据工程师，我想让来源 ID 全局唯一，以便任务派发、审核记录和日志可以稳定关联。
37. 作为数据工程师，我想让字段缺失时显式写 null 或未知，以便不编造标准号、文号、日期和授权信息。
38. 作为审阅者，我想让数据库变更建议单独成文，以便后端修改和爬虫实现可以分开评审。
39. 作为审阅者，我想让文档明确哪些表新增、哪些表补列、哪些表不改，以便评估迁移风险。
40. 作为审阅者，我想让文档说明前台展示策略，以便全量数据入库后页面不会出现空壳内容。
41. 作为审阅者，我想让文档说明采集频率和变更检测方式，以便调度器知道什么时候抓、抓什么。
42. 作为审阅者，我想让文档说明每个来源的实施优先级，以便按官方高价值来源先行推进。
43. 作为审阅者，我想让受限来源被明确标记，以便不会把禁止自动采集的页面当作普通来源实现。
44. 作为审阅者，我想让账号密码不进入任何文档或仓库，以便登录态只作为运行环境事实处理。
45. 作为项目维护者，我想让本次只产生文档，以便当前阶段先冻结设计而不引入未评审的运行代码。

48. 作为项目维护者，我想让最终验收检查来源覆盖、链接可访问性、样本一致性和 JSON 合法性，以便交付可被后续 agent 直接使用。

## Implementation Decisions

### 工作范围

- 本次只修改 `crawler` 子项目，只产生设计文档、来源清单、样本说明、下载记录和数据库变更建议。
- 不修改粤乡智匠后端、数据库 schema、前端页面、业务数据、正式数据库或部署配置。
- 不创建 PR，不创建 issue，不发布到远程 tracker。
- 使用现有 `crawler` 分支和该分支对应的 worktree。
- 文档根为 `crawler/docs`，下载根为 `crawler/download`。
- 单个下载文件不得超过 100MB。超限文件只在对应域名目录写 `OVERSIZE.md`，记录 URL、大小、原因和人工处理建议。

### 双数据库架构

采集系统使用两套 SQLite 数据库和一层转换器。

采集库分为三层:

- raw: 原始 HTML、JSON、XLSX、PDF 元数据和响应快照。每条记录至少包含来源 ID、请求 URL、取得时间、内容类型、文件大小、SHA-256、HTTP 状态和来源页面 URL。
- stage: 按来源原始结构整理的列表项、详情项、文件行和关联项。来源字段可以保留原名，不做跨来源统一。
- std: 跨来源统一后的标准实体，包括认证农产品、非遗项目、招聘岗位、方言点、方言词条和来源引用。

粤乡智匠业务库只承接已经决定发布或可展示的数据。业务库不保存抓取状态、原始 HTML、失败重试和来源差异。

转换器只读取 std 层，不直接读取页面或来源文件。转换器负责自然键、去重、字段映射、冲突判断、人工字段保护、发布状态、导入批次和回滚记录。

### 数据源与访问等级

来源按以下优先级处理:

1. 政府和官方机构原始公告。
2. 官方名录查询系统和附件。
3. 学术机构和非遗官方机构。
4. 行业招聘站。
5. 商业聚合站和二次整理来源。
6. UGC 和无法核验来源。

每个来源必须标注一种访问等级:

- public: 无需登录，可直接通过 HTTP 或 Playwright 验证。
- login-required: 需要登录，文档只记录事实和操作方式，不记录账号密码。
- robots-restricted: robots 禁止自动采集，只登记为受限候选，不自动抓取正文。
- manual-only: 只能人工查看或人工核验，不自动采集。

`ihchina.cn` 优先使用 Playwright。只有确实需要登录时才使用已登录的内置浏览器。

`zhongguoyuyan.cn` 当前 robots 全站禁止抓取，只能登记为受限来源。

### 来源覆盖

首批来源包括:

- 国家级非遗: `ihchina.cn`。
- 全国名特优新与特质农品: `aqsc.agri.cn` 和农业农村部相关公告页。
- 地理标志: `cnipa.gov.cn` 和地理标志检索系统。
- 农业与病虫害扩展来源: 农业农村部、全国农技推广服务中心、广东省农业农村厅和地方病虫害测报来源。
- 天气: `weather.com.cn`，只登记实时 API 候选。
- 招聘: `nzrc.com.cn`、`nongmuhr.com`、`5ajob.com`，并补充全国农业与乡村岗位相关的政府和事业单位来源。
- 方言: `dialect.org.cn`、`ling.cass.cn`、`cnopendata.com`、`zhongguoyuyan.cn`。
- 手工技艺: `ihchina.cn` 和 `feiyiw.cn`。
- 其他由 Tavily 或 Anysearch 发现并实际验证的公开来源。

### 数据范围

国家级非遗按 3610 个子项全量采集。第一批至少包含列表接口字段、正文、详情页结构、传承人、相关项目、相关资讯和相关学术。采集库要尽量保存公开可见内容和原始响应。转换器只把需要展示、审核或运营的字段发布到业务库。

农产品覆盖:

- 全国名特优新农产品。
- 全国特质农品。
- 农业、食品、饮料、酒类、中药材和水产相关地理标志产品。

排除纯工艺品和非食品类工业品。认证类型必须用独立字段区分，不能把名特优新、特质农品和地理标志混为同一口径。

招聘覆盖全国农业、畜牧、水产、种植、乡村基层服务和乡村治理相关岗位。列表页用于发现和翻页，详情页用于补全岗位描述、学历、经验、联系方式、发布时间和截止时间。

方言采用新的规范化模型，现有三张方言展示表继续服务前台。

天气只记录 API 候选、请求方式、城市编码和返回字段，不建立历史天气表。

### 业务库演进建议

数据库变更建议单独成文，至少覆盖:

- 新增认证农产品主表和来源表。
- 非遗项目继续进入现有手工技艺主表，并补充来源、项目编号、类别、批次、类型、保护单位、地区、可教学标记、内容哈希和导入时间。
- 新增招聘岗位主表和来源表，现有策展招募公告和企业岗位表保持不变。
- 新增方言点、方言词条和词条来源表，现有方言展示表保留。
- 天气不建表。

每项变更必须给出字段、自然键、索引、迁移顺序、兼容策略和回滚方式。

### 前台展示策略

全量数据可查、可浏览、可跳转来源详情页。

非遗列表默认展示全部项目。只有标记为可教学的项目展示完整教学步骤、视频和采购指南。没有教学内容的项目显示基础资料、来源链接和项目正文，不显示空步骤区。

农产品按认证类型、省份、县域、品类和水产等条件筛选。

招聘数据与现有策展公告、企业站内岗位分开呈现，避免用户误以为公开采集岗位支持站内投递。

### 自然键与转换规则

建议自然键:

- 认证农产品: 认证类型、产品名称、行政区划。
- 非遗项目: 项目编号、申报地区或单位、项目名称。
- 招聘岗位: 来源站、原始详情 URL。
- 方言词条: 方言点、词条文本、来源。

转换规则:

- 官方原始公告优先于第三方整理。
- 同一自然键重复导入时执行 升级写入。
- 运营手工修改过的字段不自动覆盖。
- 无法自动裁决的冲突写入冲突记录，保留两侧字段值、来源 URL、取得时间和冲突原因。
- 每次导入记录批次、开始时间、结束时间、来源、记录数、成功数、跳过数、冲突数和失败原因。
- 支持按批次撤销尚未被人工修改的导入结果。

### 文档组织

最终文档至少包含:

- 总索引和实施批次。
- 领域词汇。
- 架构决策记录。
- 每个来源一份来源文档。
- 每个来源一份独立审核文档。
- 数据模型文档。
- 粤乡智匠目标表变更建议。
- 转换器设计。
- 农产品、非遗、招聘、方言和天气字段映射。
- 采集规则、质量验收和上线顺序。
- 机器可读来源清单。

来源文档必须包含来源名称、域名、主管机构、内容域、优先级、首页 URL、列表页 URL、详情页 URL 模式、请求方式、分页参数、DOM 选择器或 API 字段、真实样本、字段映射、数据量估算、更新频率、变更检测、访问等级、版权说明、详情 URL 和验证时间。

### Agent 编排

实施分为六个波次:

1. 规划: 冻结来源 ID、模板、任务依赖和验收标准。
2. 官方高价值来源: 非遗、地理标志、名特优新、农业和天气。
3. 招聘来源: 三个招聘站和补充的政府招聘来源。
4. 方言与手工技艺来源。
5. 数据模型和转换器设计。
6. 汇总、独立审核和最终分支审查。

每个来源配一个实现 agent 和一个独立审核 agent。实现 agent 只写该来源文档和对应下载目录。审核 agent 只写该来源审核记录。共享索引和机器清单由规划或汇总 agent 单独写入，避免并发冲突。

## Testing Decisions

本次只交付文档，不实现运行时爬虫或转换器。测试重点是可复核性和契约稳定性。

### 文档层的最高测试缝

最高测试缝是来源契约，包括每个来源文档和机器可读来源清单。所有后续爬虫实现都从该契约读取来源、入口、分页、字段和访问等级。

第二层测试缝是采集库三层契约。raw、stage 和 std 的字段与职责必须能从文档独立验证。

第三层测试缝是转换器契约。转换规则只依赖 std 层和业务库目标表，不依赖具体页面结构。

### 验收方式

- 对每个关键页面或接口使用 Playwright 或实际 HTTP 请求重新访问，记录验证时间和结果。
- 对每条样本使用文档中的详情 URL 或承载页 URL 打开，确认真实存在并能定位同一记录。
- 对每个 JSON API 记录请求参数、响应字段和至少一条样本。
- 对每个文件附件记录原始 URL、文件类型、大小、字段结构和样本行。
- 对每个 DOM 选择器在真实页面上执行一次定位，确认结果非空。
- 对 `sources.json` 做 JSON 合法性、ID 唯一性和目标表引用检查。
- 对每个来源核对实现文档与审核记录，审核结论只能是 `approved`、`approved-with-gaps` 或 `blocked`。
- 对下载目录核对文件大小、SHA-256 和超限说明。
- 对数据库变更建议核对新增表、补列、索引、自然键、迁移顺序和回滚方式。
- 对转换规则核对官方优先、升级写入、人工字段保护、冲突记录和批次回滚。

### 好测试的标准

测试应验证外部可观察行为，不验证文档内部措辞或 agent 的实现细节。来源测试关注 URL 是否可访问、字段是否可得、样本是否可复现。转换器测试关注自然键、去重、冲突、人工保护和回滚结果，不关注 SQL 写法。

### 既有参照

粤乡智匠现有测试强调接口输出形状和业务行为，不锁死实现细节。采集文档验收沿用同一原则，锁来源契约、样本可复现性和转换结果，不锁文档排版。

## Out of Scope

- 不实现爬虫代码。
- 不实现调度器、重试队列、代理池或反爬策略。
- 不修改粤乡智匠后端、数据库、前端或部署配置。
- 不创建正式数据库迁移。
- 不写入粤乡智匠业务数据库。
- 不创建 PR、issue 或远程 tracker 条目。
- 不批量下载超过单文件 100MB 的文件。
- 不保存账号密码、会话 Cookie 或登录凭据。
- 不采集个人简历、求职者隐私、企业联系人隐私或需要登录后才可见的非公开内容。
- 不自动采集 robots 明确禁止的页面。
- 不把第三方文章全文发布到粤乡智匠业务库。

## Further Notes

本轮讨论已经确认两套数据库和转换器的方向。采集库承担完整性和可追溯性，业务库承担展示和运营。这样可以在网站初期快速扩大数据量，同时保留后续改表、换源和撤销导入的空间。

所有易变字段，例如招聘截止时间、联系电话、价格和天气，必须记录取得时间并标注时效风险。

所有来源必须提供可回溯来源页面。有单条详情页时保存直接详情 URL；没有时保存长期承载页 URL 和非空 locator。只给站点首页或列表首页且无法定位记录的，不算完成。

`ihchina.cn` 的列表数据已经有可验证的公开 JSON 入口，详情页可以直接打开。非遗项目正文和相关资源应尽量保存在采集库，转换器按展示需要决定发布范围。

全国名特优新公告通常通过 XLSX 附件提供结构化数据。文件应放在对应域名下载目录，文档记录字段结构和样本行，文件本身不复制进 Markdown。

`zhongguoyuyan.cn` 当前 robots 全站禁止抓取，文档只能登记来源、访问限制和人工核验方式。

最终交付需要在 `crawler` 分支提交。提交前完成来源覆盖审查、链接与样本复核、JSON 校验、文档交叉引用检查和一次分支级代码审查。

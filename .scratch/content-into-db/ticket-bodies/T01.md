## What to build

落地权限模型：新增 `backend/core/permissions.py`，持有全站唯一的能力表 `CAPABILITIES` 与
`require_capability` 装饰器。能力命名 `<域>.read` / `<域>.manage`，空元组表示公开。
覆盖农时、病虫害、技艺、方言、招募、案例、政策、课程、岗位、用户、审核十一个能力域。

- `CAPABILITIES` 至少含 `farming.read/manage`、`pest.read/manage`、`craft.read/manage`、
  `dialect.read/manage`、`recruit.read/manage`、`case.read/manage`、`policy.read/manage`、
  `course.manage`、`job.manage`、`user.manage`、`review.moderate`，取值见 spec 5.1 节。
- `operator` 是 `super_admin` 的子集：`user.manage` 与 `review.moderate` 显式不含 `operator`。
- 每个 `backend/db_domains/*.py` 模块加一行 `CAPABILITY = '<域>'`，标注它服务的能力域，
  让 `tools/check_architecture.py` 有判据。
- 领域路由文件里的 `role != 'x'` / `role == 'x'` 硬判改为 `require_capability(...)`。
  `require_role` 保留，行为不变。
- 修掉两个既有失败用例（`test_get_students` / `test_get_teacher_dashboard`，
  原因是没有带 `X-Session-Id` 头）。

本票据零数据变化：不加表、不改列、不动 `domain_data/`、不动 SQL。

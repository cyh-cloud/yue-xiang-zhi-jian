## Problem Statement

后端目前是一个 6032 行的单文件应用加一个 3346 行、混着 33 张表的数据层。领域之间只靠注释横幅分隔，
没有物理边界：任何一处改动都可能牵连看似无关的功能，改动前无法判断影响面。

具体表现：

- 想改「教师名册」时，打开的文件里同时装着病虫害诊断提示词、直播话术评分规则和二十四节气算法。
- 数据层里，审核状态变更会反向写入课程、岗位、采购、3D 模型四个领域的表；未读总数横跨通知、消息、
  就业三个领域的五张表；能力档案横跨四个领域的六张表。任何一处领域演进都会牵动其他领域。
- 同一个「按标识取用户」的函数在数据层里定义了两遍，后一份覆盖前一份，语义只能靠覆盖顺序隐式维持。
- 新增功能时没有地方可放：既有的领域边界只存在于注释里，新代码只能继续往唯一的大文件里堆。

使用者是后续所有要在这个仓库里改后端的人：他们需要在动手前就知道改动会波及哪里，
需要能只读一个领域的代码就理解一个领域，需要新增功能时有明确归属。

## Solution

把后端按领域拆成一组独立模块，领域之间不直接依赖。共享的横切能力收进三个共享模块，
跨领域的数据需求收敛为显式的窄接口，对外行为（URL、请求响应结构、状态码、错误码）完全不变。

拆分后的形状：

- 一个应用工厂负责组装，入口文件只做创建应用与注册蓝图，不再承载任何业务。
- 共享层三个模块：应用级横切（应用工厂、跨域配置、会话与角色鉴权、限流、统一错误响应）、
  上游模型调用（配置、同步与流式补全、多模态调用）、纯函数工具（节气计算、农技口径正则、
  直播朗读评分、文案评分、下拉选项拼装）。
- 数据层按领域切分，外加一个连接工厂、一份建表定义和一组播种逻辑。
- 领域数据模块（病虫害知识、公开招聘、成功案例、政策、农事基础数据）原样搬入新结构，内容不改。
- 一个领域一个路由蓝图；领域之间禁止互相 import。

三条跨域收敛规则同时落地：审核状态变更收敛为单一入口并按内容类型分派；
未读总数由持有方显式调用其他领域的计数窄接口；能力档案由就业域组合调用其他领域的窄接口拼装，
不再直接读别人的表。

## Implementation Decisions

**拆分深度**：只做搬移与提取，不改任何对外行为。URL、请求字段、响应键、状态码、错误码、
数据表结构全部保持不变。不做路由/服务/仓储三层重构，不改内部函数签名。

**范围**：单文件应用与混表数据层两层同构拆分。五个领域数据模块原样搬入新结构，内容一行不改。

**实施补充**：「内容一行不改」指数据本体、函数签名、常量值，措辞与包内导入除外。`pest_data.py` 有 3 处例外，均为搬迁必需：注释里「项目根」改为「仓库根」（与 ADR 0001、`repo_paths.py` 的措辞统一）、顶层 import 改为包内相对导入、以及一行说明该改动的注释。其余 4 个模块 git 显示 `R100` 零改动。
本地脚本、前端文件、部署配置不在本次范围。

**切分单位**：一个领域一个路由蓝图。领域边界由业务内聚性决定，URL 前缀只作命名参考。
一个 URL 前缀可以拆成多个领域模块，但一个模块不得横跨多个领域。具体而言：

- 农业培训域：农技问答、农事日历、作物订阅与到期提醒。
- 病虫害诊断域：文字与图片诊断、本地知识库降级匹配、结论来源标注。
- 病虫害速查域：按作物的条目查询。
- 电商运营域：带货话术、商品文案、客服对练。
- 直播实训域：直播朗读实录分析、三类实训提交与记录查询。该域体量最大，整体独立成模块。
- 手工技艺域：技艺列表与详情。
- 本土资源域：方言问答、成功案例、政策信息。
- 就业对接域：岗位浏览与筛选、投递、收藏、求职意向。
- 就业能力档案域：能力档案、在线简历、AI 简历辅助。
- 教师管理域：名册与学员的增删改查、账号绑定。
- 教学支撑域：课程与材料、3D 模型、公告、实训批改、学情分析。
- 社区域：讨论帖与评论。
- 认证域：登录、登出、会话校验、注册。
- 用户资料域：个人资料读写、改密码。
- 超级管理员域：用户管理、内容审核、系统公告、评论与帖子删除。
- 政府域：政策管理与仪表板。
- 企业域：岗位管理、投递处理、统计。
- 公开域：首页统计、公开课程、公开 3D 模型、系统公告、评论与讨论的公开读。
- 静态资源域：首页与静态文件兜底。

**共享层边界**：只有三个共享模块，且共享层不感知任何具体领域。

- 应用级横切模块：应用工厂、跨域配置、会话取用户、角色装饰器、限流与限流键、统一错误响应。
  这些是被调用区块数最多的横切能力（会话鉴权被 10 个领域使用，AI 统一出口被 8 个领域使用，
  限流与其键构造各被 7 个领域使用）。
- 上游模型调用模块：模型配置、同步补全、流式补全、多模态补全。含「是否已配置」「问答用哪个模型」
  这类只与上游有关的判断。
- 纯函数工具模块：节气计算、农技口径（农药剂量提示）判定、直播朗读评分、文案评分、下拉选项拼装。
  这些函数零领域依赖，任何领域都可能用到。

**边界件归属**：只跨两个领域的 helper 按「本质归属」决定去留，不按调用次数。

- 消息身份护栏进应用级横切模块：它本质是鉴权，放消息域会让通知域反向依赖消息域。
- 实训状态标签归直播实训域，实训批改域显式引用。
- 电商作物名校验归电商运营域，直播实训域显式引用。
- 农技问答系统提示词连同它依赖的作物名解析、农业知识常量与农技口径常量，整组下沉农业培训域。
  它的两个调用方都在问答路径上，留在共享层会让每个领域都能改农技口径。
- 农技口径（农药剂量）判定本身留纯函数工具模块，因为病虫害诊断域与方言问答域也调用它。
- 「是否已有简历」归就业能力档案域，就业对接域显式引用。

**数据层切分**：按领域分组，一个领域一个模块。连接工厂单独一个模块，是全数据层唯一的连接入口。
建表定义单独一处。播种逻辑按领域归组，跨领域的播种步骤由组装方显式按顺序调用。

**跨域收敛一，审核状态变更**：审核域对外只暴露一个「按内容类型改审核状态」的入口。
由它按内容类型分派到对应领域，各领域只暴露「改我这张表的审核字段」一个窄接口。
路由层不再直接碰任何领域表。分派表集中维护，新增可审核内容类型时只需加一行。

**跨域收敛二，未读总数**：留在通知域，改为显式调用消息域与就业域各自的未读计数窄接口，
不再由通知域直接读消息表与投递表。

**跨域收敛三，能力档案**：留在就业能力档案域，改为组合调用：用户基础信息取认证与用户域、
证书与实训记录取教学支撑域、积分余额取积分侧，就业域只负责拼装，不再直接读别人的表。

**重复定义清理**：数据层中「按标识取用户」与「更新用户资料」各存在两份定义，后一份覆盖前一份。
保留实际生效的那份（按用户名语义、返回全字段、资料更新支持全部字段），删除被覆盖的两份，
并在原处留一行说明历史，避免后人误以为按主键查才是真相。

**路径基准**：所有文件系统路径统一以仓库根为基准，不再以模块文件所在目录为基准。
上传落盘目录、数据库目录、静态资源根目录、环境变量文件位置，全部从同一个仓库根常量推导。
这样上传目录与静态资源放行目录天然指向同一处。环境变量仍是唯一配置入口，
所有可调项继续从环境变量读取，默认值内聚在各自模块，拆分不改变配置方式。

**入口兼容**：部署入口（serverless）与本地启动入口继续以「导入应用对象」与「初始化数据库」
两个动作接入，不引入新的启动约定。测试客户端仍能直接拿到应用对象。

**目录骨架**：应用工厂与蓝图注册留在入口文件；共享层三个模块；数据层一个连接模块、
一个建表模块、一组播种模块、一组领域数据模块；路由层一个领域一个蓝图；
五个领域数据模块原样搬入。

**验收门槛**（四条，可机械检查）：

- 单测套件全部通过。
- 端到端套件全部通过。
- 静态检查确认任意两个领域路由模块之间不存在 import 边；共享模块不得 import 领域模块。
- 单个领域路由文件不超过 600 行，超过则继续在该领域内切分。当前最大区块远超此数，
  必然需要二次切分，这是预期而非例外。

## Testing Decisions

好的测试只测外部行为，不测内部结构：测 URL、请求响应结构、状态码、错误码与数据可见性，
不测模块怎么划分、函数放哪、内部怎么调用。

- 既有单测套件（23 项）与端到端套件（13 个 spec）是本轮的主要回归保障，
  它们已经锁定了 URL、JSON 键与状态码。拆分后两者必须全绿，且**不改任何断言期望**。
- 端到端的所有权矩阵 spec 覆盖面最广，逐条核对「谁能读什么」，是越权类回归的核心防线，优先跑。
- 审核门禁相关 spec 覆盖「发布-审核-可见-撤销」全链路，是审核收敛的主要验证点。
- AI 契约相关 spec 在上游未配置时断言明确失败，是「不返回假结果」红线的守门测试。
- 唯一需要改动的测试是模拟「上游未配置」的那一处：它原来通过改写入口文件上的开关实现。
  拆分后该开关由上游调用模块持有，且路由模块在导入时就绑定了名字，改写入口文件上的同名属性会失效，
  导致该用例从「验证明确失败契约」退化成「真的去打上游」。改为直接改写真正的持有者。
  这是测试适配拆分形状，不是放宽断言。
- 不新增针对新模块结构的测试。拆分本身不产生新行为，为新结构写测试只会把实现细节钉死。

## Out of Scope

- 行为变更：本次不做任何功能增减、口径调整或缺陷修复。发现的既存问题（如建表后无人读写的表）
  只记录，不在本次处理。
- 分层重构：不引入服务层与仓储层，不改内部函数签名与返回结构。
- 五个领域数据模块的内容修订。
- 前端文件、本地一次性脚本、部署配置的调整。
- 新增针对新模块结构的测试。
- 数据库迁移：表结构不变，无 schema 变更。

## Further Notes

- 本次拆分的最大风险不是「搬错位置」而是「静默改变行为」。三处高危点：
  审核分派漏掉一种内容类型会让某类内容永远卡在审核中；跨域聚合改成组合调用时漏一个表会让
  未读数或档案字段悄悄变少；路径基准改错会让上传文件存得下但取不回。每处都要有对应的端到端断言兜底。

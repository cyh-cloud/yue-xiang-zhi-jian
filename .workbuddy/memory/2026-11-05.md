### 踩到的坑

- **同一秒两次提交撞文件名**：原用 `int(time.time())` 做后缀，第一次提交成功后重交被 409 拒绝，
  清理时按同名删掉了第一次的文件。改 uuid 前 12 位。
- `users.get_user_by_username()` 只 SELECT 6 列（无 company_name/phone），审核侧「账号公司名」
  恒为空、「名称一致」恒为 false。改用 `get_user_by_id()`（它其实按 username 查、SELECT *）。
- 早前用 PowerShell `Set-Content -Encoding UTF8` 改测试文件时写进了 BOM，`ast.parse` 直接报
  `invalid non-printable character U+FEFF`（跨域视图测试红）。已按二进制方式剥掉 BOM。
- `npm run build`（含 vue-tsc）在本机失败于 `axios` 缺 `index.d.ts`（node_modules 安装不全，
  package.json 指向的文件不存在）。属既有环境问题，未改仓库；用 `npx vite build` 验证组件可编译。

### 审核队列里的 48 条「岗位 #35x」是我跑测试留的脏数据（2026-11-06 发现并清理）

- 现象：管理端「内容审核」待审 46 条，提交人是 `qual_xxxxxxxx`，点进去只有「岗位 #358」。
- 根因：`tests/test_enterprise_qualification.py` 的 tearDown 直接 SQL 删 `job_listings` 与
  `users`，**没有删 `content_reviews`**；每一次跑测试都给队列灌一批孤儿记录。
- 数据修复：备份 `data/yuexiang.db.bak-review-orphans-20261106` → 删除 48 条孤儿，
  明细留档 `output/review-cleanup/orphans-20261106.json`，剩余 7 条（2 岗位 + 5 案例）。
- 代码修复：
  1. `reviews._CONTENT_ALIVE_SQL`：列表与页签计数都过滤「目标内容已不存在」的记录，
     口径一致（否则页签显示 46、列表却是空的）；
  2. 测试 tearDown 改走 `reviews.delete_reviews_for()`（两个测试文件都补了）；
  3. 管理端岗位详情改用新增的 `employment.get_job_for_review()`（不带公开过滤），
     否则「已关闭」的岗位在审核列表里也会只剩编号。
- 连带：`test_db_domain_boundaries` 的 `ALLOWED_FOREIGN_TABLES['reviews']` 登记了
  四张内容表的只读存在性检查，并写明理由。
- 教训：**测试清理要删干净到审核记录**。跨域删除一律走属主域的删除入口，不要自己写 SQL。

### 后端没重启 → 新路由落到静态兜底（用户实际踩到）

- 症状：企业资质页显示「认证状态加载失败 / 文件不存在」。`/api/enterprise/qualification`
  实际回 404 + `{"code":"not_found","message":"文件不存在"}`——这是 `domains/static_files`
  的 catch-all（`/<path:filename>`）在接，说明**路由压根没注册**，不是业务报错。
- 真因：`backend/run.py` 写死 `debug=False, use_reloader=False`，改完后端必须手动重启；
  用户的 yx-backend 窗口是在改代码之前开的。
- 处置：kill 5000 端口旧进程 → 用 `py -3.9 run.py` 重启 → 在线验证 `status=approved, verified=True`。
- 防复发：`run.py` 增加 `YX_DEV_RELOAD` 开关（默认关，`start-dev.bat` 里设为 1），
  之后改后端会自动重启。**以后凡是「新接口 404 且 message 是『文件不存在』」，先怀疑服务没重启。**

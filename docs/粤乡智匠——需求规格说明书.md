1. 引言

1.1 编写目的

本文档旨在详细定义"粤乡智匠——基于AI实训系统的农村本土人才赋能平台"的功能需求、非功能需求和接口需求，为系统的设计、开发、测试和验收提供依据。本文档的预期读者包括：项目管理人员、开发工程师、测试工程师、UI/UX设计师以及利益相关方。

1.2 项目背景

随着国家乡村振兴战略的深入推进，农村地区对农业技术、电商运营和传统手工艺技能的需求急剧增长。然而，传统教育培训模式面临师资稀缺、理论脱离实践、用户数字素养差异大等核心痛点。粤乡智匠项目旨在利用人工智能技术，构建一套低成本、高互动的AI实训系统，为广东省农村本土人才提供技能培训、电商运营、非遗传承和就业对接的一站式服务。

1.3 文档范围

本文档覆盖粤乡智匠平台的全部功能需求，包括：学员端六大核心学习模块、教师工作台、企业中心、政务工作台、超级管理员后台和社区互动子系统。同时涵盖系统的非功能性需求、接口需求和数据需求。

1.4 术语定义

| **术语** | **释义** |
| --- | --- |
| AI实训 | 利用人工智能大模型提供模拟训练环境，辅助用户进行实操练习 |
| 非遗技艺 | 非物质文化遗产手工艺技术，本项目特指广绣、潮汕木雕、石湾陶艺、阳江漆器 |
| SSE | Server-Sent Events，服务器推送事件，用于AI流式输出 |
| WAL | Write-Ahead Logging，SQLite的预写日志模式，提升并发性能 |
| Fallback | 降级机制，当云端AI服务不可用时自动使用本地知识库 |
| PWA | Progressive Web App，渐进式Web应用，支持离线访问 |
| ARIA | Accessible Rich Internet Applications，无障碍富互联网应用规范 |
| 门户 | 面向特定角色的功能工作台，拥有独立的界面和专属功能 |

2. 总体描述

2.1 产品视角

粤乡智匠是一个基于Web的B/S架构应用，采用"原生前端 + Flask后端 + 云端大模型API"的三层架构。系统面向广东省农村地区，为不同角色用户提供差异化的功能门户。系统通过AI大模型提供智能化服务，同时保留本地知识库作为降级保障。

2.2 用户角色与特征

| **角色** | **特征描述** | **核心需求** |
| --- | --- | --- |
| 学员（农民/待业青年/学生） | 数字素养参差不齐，部分为中老年人；主要使用手机访问；存在方言使用习惯 | 学习实用技能、获取就业机会、了解政策信息 |
| 教师（培训讲师） | 具备专业技能，需要管理班级和跟踪学情 | 管理学员、发布作业、分析学情、AI辅助教学 |
| 企业用户 | 农业合作社、电商基地等用人方 | 发布招聘和求购信息、筛选人才 |
| 政府人员 | 地方农业农村部门工作人员 | 发布政策与资讯、监控地区人才发展数据 |
| 超级管理员 | 平台运营维护人员 | 用户管理、内容审核、系统配置 |

| **维度** | **要求** |

| 服务器操作系统 | Windows / macOS / Linux |
| Python版本 | 3.8 及以上 |

| 网络要求 | 稳定的互联网连接（AI功能需要） |

2.4 假设与约束

假设SiliconFlow API服务持续可用，且API Key有效

假设用户具备基本的智能手机或电脑操作能力

约束：系统数据存储在本地SQLite文件中，不支持分布式部署

约束：AI回复质量取决于大模型能力，存在生成内容不准确的可能

约束：Vercel部署环境下数据库为非持久化存储，生产环境需接入外部数据库

约束：首期面向广东省农村地区，内容以广东本土特色为主

3. 功能性需求

REQ-AUTH-001：系统应支持用户注册（用户名、密码、姓名、角色）

REQ-AUTH-002：系统应支持用户登录，密码采用SHA-256加盐哈希存储

REQ-AUTH-003：登录成功后创建会话，会话有效期可配置（默认24小时）

REQ-AUTH-004：系统应支持五种角色：student（学员）、teacher（教师）、enterprise（企业）、government（政府）、super_admin（超级管理员）

REQ-AUTH-005：不同角色登录后应自动进入对应门户页面

REQ-AUTH-006：未登录用户可访问主站（index.html），但不能使用需要登录的功能

REQ-AUTH-007：系统应支持退出登录，清除服务端会话

REQ-AUTH-008：系统应支持会话过期后自动跳转登录页

4. 非功能性需求

4.1 性能需求

PERF-001：页面首次加载时间应在3秒以内（正常网络条件下）

PERF-002：API接口响应时间应在500ms以内（非AI接口）

PERF-003：AI接口流式输出首字节时间应在5秒以内

PERF-004：系统应支持至少50个并发用户同时使用

PERF-005：数据库查询应通过索引优化，单表查询应在100ms以内

4.2 安全性需求

SEC-001：用户密码必须采用SHA-256加盐哈希存储，禁止明文存储

SEC-002：会话ID应为随机生成的UUID，防止会话劫持

SEC-003：AI API Key应通过环境变量配置，禁止硬编码在代码中

SEC-004：API接口应对未登录用户返回401状态码

SEC-005：用户只能访问自己角色权限范围内的功能页面

SEC-006：文件上传应限制文件大小（默认16MB）

SEC-007：敏感操作（删除、审核）应有确认提示

4.3 可用性需求

USA-001：界面采用响应式设计，适配320px-1920px宽度的设备

USA-002：导航结构清晰，面包屑导航层级不超过3层

USA-003：关键操作按钮应有明确的视觉反馈

USA-004：系统应支持深色/浅色主题切换

USA-005：表单应有输入验证和错误提示

USA-006：加载过程应有加载动画或骨架屏提示

USA-007：系统应支持键盘导航和ARIA无障碍标签

USA-008：系统应提供新手引导，首次使用时展示功能介绍

4.4 可靠性需求

REL-001：当AI服务不可用时，农业问答应降级到本地知识库

REL-002：当AI服务不可用时，电商/手工相关功能应向用户友好提示"AI服务暂时不可用"

REL-003：系统异常应记录日志，不应向用户暴露技术细节

REL-004：数据库操作应有事务保护，异常时自动回滚

REL-005：前端应对API调用失败有统一的错误处理机制

4.5 可维护性需求

MAIN-001：代码应遵循PEP 8规范（Python）和一致的JavaScript编码风格

MAIN-002：核心模块（js/core.js）与业务脚本（script.js）应分离

MAIN-003：门户通用逻辑（portal.js）应由多角色页面共享

MAIN-004：API端点应按模块分组，路由命名应有统一规范

MAIN-005：数据库初始化脚本应支持幂等执行（CREATE TABLE IF NOT EXISTS）

MAIN-006：系统应提供单元测试覆盖核心API端点

4.6 可移植性需求

PORT-001：系统应支持在Windows、macOS、Linux三大平台上运行

PORT-002：系统应支持本地运行和Vercel Serverless部署两种模式

PORT-003：数据库路径应根据部署环境自动切换（本地data/目录 vs Vercel /tmp目录）

PORT-004：前端代码应兼容Chrome、Edge、Safari、Firefox四大主流浏览器

5. 接口需求

5.1 用户界面需求

UI-001：主站（index.html）应采用单页面设计，通过标签切换六大功能模块

UI-002：多角色门户应采用侧栏导航+内容区的经典布局

UI-003：配色方案以绿色为主色调（#10b981），体现乡村振兴主题

UI-004：移动端侧栏导航应支持汉堡菜单交互

UI-005：全平台应统一使用Font Awesome 6.0图标库

UI-006：表格数据应有斑马纹背景提升可读性

UI-007：卡片组件应有统一的圆角、阴影和间距规范

5.2 外部接口需求

EXT-001：AI服务接口：通过HTTPS调用SiliconFlow API（/v1/chat/completions），支持流式(SSE)和非流式两种模式

EXT-002：AI模型默认为DeepSeek-V3/Qwen3-32B，可通过环境变量AI_MODEL切换

EXT-003：图标资源通过CDN加载（cdn.bootcdn.net），需网络连接

EXT-004：所有内部API应遵循RESTful规范，返回统一的JSON格式：{"success": bool, "message": str, ...}

6. 数据需求

系统采用SQLite作为数据存储方案，需要持久化以下核心数据实体：

**用户数据：**用户名、密码哈希、姓名、角色、邮箱、手机、公司名称、地区、个人简介

**会话数据：**会话ID、关联用户、登录时间、过期时间

**积分数据：**用户ID、积分余额、积分变动历史（JSON）

**证书数据：**用户ID、证书名称、状态、进度、获得日期

**学员数据：**学员ID、关联用户、姓名、班级、学习方向、学习进度、状态

**公告数据：**标题、内容、类别、是否置顶、创建时间

**作业数据：**标题、描述、学习方向、截止日期、满分、创建时间

**作业提交数据：**关联作业、学员ID、提交内容、评分、反馈、状态

**考勤数据：**考勤标题、状态、创建时间、关闭时间；签到记录（考勤ID、学员ID、签到状态）

**消息数据：**发送者、接收者、内容、已读状态、创建时间

**通知数据：**用户ID、类型、标题、内容、已读状态、关联信息

**案例数据：**标题、摘要、内容、类别、配图、地点

**政策数据：**标题、内容、类别、来源、发布状态

**岗位数据：**标题、公司、地点、薪资、类型、类别、描述、审核状态

**求职数据：**岗位ID、用户ID、状态、申请时间

**审核数据：**内容类型、内容ID、提交者、状态、审核意见、审核者

数据库默认存储在 data/yuexiang.db，Vercel环境使用 /tmp/yuexiang.db。启用WAL模式和WAL检查点，外键约束开启。密码采用SHA-256加随机盐哈希存储。

# 开发宪法执行规则

`docs/adr/` 下的架构决策记录是本项目的开发宪法。所有需求、实现、测试和审查都必须遵循。

## 只读规则

- 现有 ADR 对全体成员只读。
- 任何成员不得修改、重命名、移动或删除 ADR 文件。
- 普通功能分支不得附带 ADR 改动。
- 实现不能通过局部例外、临时开关或口头约定绕过 ADR。

## 开工前

进入后端、数据库、权限、数据流或跨领域改动前，先读受影响的 ADR。实现方案必须与裁决一致；能引用现有 ADR 时，在功能说明里注明编号。

## 冲突处理

需求与 ADR 冲突时，按以下顺序处理：

1. 停止实现，保留复现步骤、相关文件和冲突点。
2. 创建 GitHub issue，打上 `conflict` 标签和严重程度标签。
3. 通知项目负责人，说明受影响的 ADR 与用户影响。
4. 由项目负责人决定是调整需求、延后实现，还是走正式宪法修订流程。
5. 在裁决落地前，功能分支保持现状，不提交绕过方案。

## 修订边界

任何成员都不得编辑现有 ADR，普通功能分支、前端成员和自动化代理也不修改宪法。需要讨论新裁决时，先创建 GitHub issue 交由项目负责人判断；普通开发流程不直接编辑现有 ADR。

## 审查要求

代码审查同时检查实现与 ADR 是否一致。发现未授权 ADR 改动时，审查结论为阻塞，先恢复原文件状态并重新提交。

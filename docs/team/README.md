# 团队开发入口

本目录是团队协作规范的入口。开工前先读本页，再按任务读对应文档。

## 默认分工

- 前端开发者负责页面、样式、交互、响应式体验、前端测试与静态资源。
- 项目负责人维护后端与数据库。其他成员参与这两部分时，按本页的例外流程执行。
- 受保护范围包括 `backend/`、`data/`、`migrations/`、数据库 schema、初始化与迁移脚本，以及会改变 API 契约的代码。
- 需求涉及新接口、字段、权限、表结构或数据迁移时，先讨论。前端用正式契约联调，不用假数据替代缺失字段。

## 新功能流程

1. 讨论目标、用户影响、接口或 schema 影响、负责人和验收方式。
2. 必须创建 GitHub issue，并打上 `feat` 标签。聊天记录、`.scratch` 或其它形式都不能替代 issue。
3. 若方案与现有宪法、契约或文档冲突，必须打上 `conflict` 标签和严重程度标签。
4. 涉及后端接口、数据库结构或 API 契约时，从最新 `main` 新开独立功能分支，例如 `feature/<short-name>`。
5. 后端与数据库改动只在该功能分支内、按已确认范围完成。
6. 涉及后端或数据库的功能完成相关验证和代码审查后合入；纯前端小功能按下一节执行。
7. 改动 `main` 前确认没有绕过讨论或超出已记录范围。

## Fix 与前端小功能

纯前端 fix 可以在当前分支直接 commit 和 push，不需要项目负责人审查。前端小功能仍按新功能流程创建带 `feat` 标签的 GitHub issue，但不触及后端接口、数据库结构、API 契约、ADR 或文档冲突时，也可以留在当前分支直接 commit 和 push，不需要另开功能分支或等待审查。提交前完成相关验证；一旦触及受保护范围或产生冲突，转为功能分支流程。

## 开发宪法

`docs/adr/` 是开发宪法，所有任务遵循。现有 ADR 对全体成员只读，任何成员不得修改、重命名、移动或删除。方案与 ADR 冲突时，停止实现，保留现场并上报项目负责人。详见 `adr-constitution.md`。
